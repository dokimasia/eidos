# RFC-0091: The frame of a data file

## Summary

We propose that a data family state the comment syntax of its file, and that the run stamp the file
with the frame of the brand in that syntax.

- `plugin.Output.Comment` declares the comment syntax of the file of a data family. The run stamps
  the file through a contract of the brand and that syntax, so a sink recognises the file by its
  frame in any clone.
- A data family without a comment syntax writes its file without a frame. A sink recognises that
  file by the digest that the manifest records.
- Under `run --check`, the line set compares the bodies of the committed file and the fresh file.
  `output.Body` returns the body of a stamped file and the number of lines above it.

## Motivation

The frame is the record that a fresh clone has of the files that a run wrote. The manifest is in the
state directory, which a repository does not commit. A sink classifies a file with the frame of its
brand as the output of the brand, and it does not read the state for that.

A sink classifies a data file through the digest that `output.Owner` declares from the manifest of
the previous generation, because the file does not have a frame (`output/disk.go`, `ownership`). A
run in a clone without the state directory does not declare a digest, so the sink classifies the
data file of the brand as foreign. The run then refuses the write with `ForeignFile`
(`workspace/plan.go`, `verdicts`).

A run of dokimi in a clone without `.dokimi/` fails as soon as its lock gains or loses a line, such
as for a new suite, because the lock is a data file:

```text
dokimi.go.lock: error EID-0056: dokimi.go.lock is a file the dokimi brand did not write, and plan "go" routes Struct storeLock there (close)
```

dokimi tells a repository to ignore `.dokimi/`, so every fresh clone and every CI job is in this
state. Only a machine that kept its state directory can change the lock.

## Detailed design

### Components

| Component | Change |
|---|---|
| `plugin.Output.Comment` | Declares the comment syntax of the file of a data family |
| `plugin.CommentSyntax.IsZero` | Reports a syntax without a line form, a block form and directives |
| `layout` | Refuses a comment syntax on a family without a name |
| `workspace` | Builds a contract for each data family with a comment syntax, stamps the file of the family through it, and compares the bodies of a line set |
| `output.Body` | Returns the body of a stamped file and the number of lines above it |
| `eidos-sdk` | The regenerated facade of `output` |

### The comment syntax of a data family

```go
// Comment is the comment syntax of the file of a data family, such as
// CommentSyntax{Line: []string{"#"}}. The run stamps the file with the
// frame of the brand in that syntax, so a sink recognises the file by its
// frame in any clone. The zero syntax leaves the file without a frame. A
// family of source files states none, because the run stamps its files in
// the comment syntax of the target.
Comment CommentSyntax
```

```go
// IsZero reports whether s is the zero syntax: Line and Blocks are empty,
// and Directives is false. It allocates nothing.
func (s CommentSyntax) IsZero() bool
```

- **Validation.** The layout refuses a family with a comment syntax and no name. The composition
  refuses a comment syntax with neither a line form nor a block form, with the error of
  `output.NewContract`.
- **Contract.** The composition builds one contract from the brand and the comment syntax of each
  data family that states one, beside the contract of the plan.
- **Stamp.** The run stamps the body that the template wrote through the contract of its family.
  The frame is the frame of a source file: the marker, one line for each plugin and each source, a
  blank line, the body, a blank line and the trailer. A plan file derives from no source, so the
  frame of a data file has no source line.
- **Ownership.** A sink classifies the file through its frame, as it classifies a source file. A
  file whose body matches the digest of its trailer is intact, a framed file with another body is
  drifted, and a file without the frame of the brand is foreign. The digest that the manifest
  records changes nothing for a file with a frame.

The lock of dokimi, whose family states the line form `#`, has this form:

```text
# Code generated by dokimi. DO NOT EDIT.
# dokimi:plugin suite

# dokimi lock 1
# Each line is one check, ceiling, refusal or unclaimed classification. Commit this file.
<one line for each check, ceiling, refusal and unclaimed classification>

# dokimi:provenance sha256:<the digest of the body>
```

### The body of a stamped file

```go
// Body returns the body of a stamped file of any brand and the number of
// lines above it: the marker, the derivation lines and the blank line
// after them. The body is the text that [Contract.Stamp] framed. Body
// returns the bytes whole, 0 and false where no frame is present.
//
// Body checks nothing, as [Read] does. It returns the body of a file that
// a person edited since its stamp as the file has it.
//
// # Allocation contract
//
// Body allocates what [Read] allocates for the record of the frame, and
// returns a part of stamped.
func Body(stamped []byte) (body []byte, above int, framed bool)
```

### The line set

- **Comparison.** Under `--check`, the run compares the body of the committed file with the body of
  the fresh file, as `output.Body` returns them. A file without a frame is its own body. The run
  splits each body at `\n` and drops the `\r` of a `\r\n` line ending. The order and the repetition
  of the lines do not matter.
- **Lines.** A removed line has its line in the committed file: its line in the body plus the lines
  above the body.
- **A committed file without a frame.** The run compares the whole committed file with the body of
  the fresh file, so a committed lock without a frame does not report a removed line for the frame
  of the fresh lock.

### Failure handling

| Failure | Behaviour |
|---|---|
| A family with a comment syntax and no name | The composition fails to build with the error of the layout |
| A comment syntax with neither a line form nor a block form | The composition fails to build with the error of the contract |
| A framed data file that a person edited | The sink classifies it as drifted, and the run refuses the write without `--overwrite-drift` |
| A file without the frame of the brand at the path of a data file with a comment syntax | The sink classifies it as foreign, and the run refuses the write without `--adopt` |
| A committed data file without a frame, in a clone without the state directory | The sink classifies it as foreign until a commit contains the framed file |

### Migration

- A data file without a frame in a workspace with the state directory has its recorded digest. The
  sink classifies it as intact, so the first run after the family states a comment syntax writes the
  framed file over it.
- In a clone without the state directory, the same file is foreign. `run --adopt` writes the framed
  file over it once.
- A reader of the file outside eidos skips the lines of the frame. They are comments of the format,
  so a reader that skips comment lines and empty lines, such as the reader of the lock of dokimi,
  reads the lines of the body alone.

### What does not change

- The frame, the stamp and the classification of every source file.
- A data family without a comment syntax, and `output.Owner`, which declares the recorded digests
  for its file.
- `--check` reports `OutOfDate` for every line-set file that differs from the fresh file.

### Verdicts

| Item | Verdict | Reason | Reverses the verdict |
|---|---|---|---|
| `Output.Comment` | in | The comment syntax belongs to the format of the data file, and only the plugin knows the format | none known |
| The frame of a source file in a data file | in | `parse`, `Read`, `Verify`, the sweep and the load gate read one grammar of the frame | a format whose first line is fixed, such as an XML declaration |
| The recorded digest for a data family without a comment syntax | in | A format without comments, such as JSON, has no place for a frame | none known |
| The comparison of the bodies under `--check` | in | The trailer changes with every body, so a comparison of the whole files reports the old trailer as a removed line | none known |

## Alternatives considered

### The manifest in the repository

A repository could commit the manifest. The manifest records the digest of every generated file, so
every change of a generated file changes a document of the manifest. The proof of a data file would
then be in a second file, and a merge can take the data file from one branch and the manifest from
another. The run assumes that a fresh clone has no state.

### A header that the plugin checks

The plugin could recognise its file by a line of the body, such as `# dokimi lock 1`. A header does
not contain a digest of the body. The run would overwrite a file that a person writes with the
header. The check of drift compares a body with its digest, so the run would also overwrite an edit
of its own file.

### The comment syntax of the target

A source file takes the contract of the plan. The lock of a Go plan would get `//` lines from that
contract, and the format of the lock has no such comment. The comment syntax belongs to the format
of the file, not to the language of the plan.

### A trailer without the marker

A trailer alone would leave the first lines of the file unchanged. `parse` finds the body after the
marker and the blank line, so a trailer alone needs a second grammar in every reader of the frame.
The marker also tells a reader of the file that a run writes it. Cargo writes such a marker as the
first line of its lock file, in the comment syntax of TOML.

## Drawbacks

- The frame adds four lines and one line for each plugin to a data file: the marker, two blank lines,
  the trailer and the plugin lines. The lock of dokimi has five more lines.
- The trailer changes with every change of the body, so the diff of every change of the file shows
  its last line.
- A reader of the file outside eidos skips the lines of the frame.
- A committed data file without a frame remains foreign in a clone without the state directory until
  a commit contains the framed file.
